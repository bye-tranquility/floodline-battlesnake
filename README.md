# Floodline

Самостоятельная соревновательная змейка на Go для Duels, Standard, Royale и Constrictor. Каждый ход рассчитывается из состояния, присланного ареной. Для игры нужны только процессор и сеть.

[Профиль VibeSnake (Floodline) на арене](https://arena.battlesnake.com/battlesnakes/eefbc819-2b24-4eec-b727-cf7441a9fee7/profile) · [Профиль игрока](https://arena.battlesnake.com/users/bye-tranquility/a6b9eedb-f5e7-47ee-bc34-cec86ec2c56f) · [Игровой сервер на Railway](https://floodline-production-ac6acf4b.up.railway.app) · [Результаты экспериментов](experiments/README.md)

## Запуск

С Go 1.23 или новее выполнить в корне репозитория:

```sh
go run .
```

По умолчанию сервер слушает порт 8080. Переменная `PORT` задаёт другой порт. Проверка метаданных — `curl http://127.0.0.1:8080/`. Сервер принимает `POST /start`, `POST /move` и `POST /end`.

Для запуска в Docker на одном ядре:

```sh
docker build -t floodline .
docker run --rm --cpuset-cpus=0 --cpus=1 -e GOMAXPROCS=1 -p 8080:8080 floodline
```

## Пример локальной дуэли

Пока первый сервер работает на порту 8080, запустить собственного тренировочного соперника в другом терминале:

```sh
PORT=8081 STYLE=food go run .
```

В третьем терминале установить и запустить официальный движок фиксированной версии:

```sh
go install github.com/BattlesnakeOfficial/rules/cli/battlesnake@v1.2.3
"$(go env GOPATH)/bin/battlesnake" play -W 11 -H 11 -g standard -m standard --seed 42 --timeout 500 \
  --name Floodline --url http://127.0.0.1:8080 --name Forager --url http://127.0.0.1:8081
```

По умолчанию играет `STYLE=search`. В дуэли Floodline моделирует одновременные ходы, постепенно увеличивает глубину и выбирает лучший ответ на худший ход противника. Оценка учитывает достижимую территорию, выходы, длину, здоровье и расстояние до еды. В Royale путь через опасные клетки расходует здоровье. В массовом Constrictor бот ищет непрерывный путь и проверяет, сколько свободных клеток останется, если ближайший соперник перекроет проход за два хода. В массовом Standard он проверяет четыре шага до выхода из окружения. В Royale он отдельно считает время прихода каждой головы, запас здоровья на дорогу к еде и обратно и восемь шагов с учётом движения хвостов. Когда остаются двое, снова включается дуэльный поиск. Новую еду и границы опасной зоны бот получает от движка каждый ход.

Сначала бот рассчитывает запасной ход. По умолчанию поиск расходует до 1 200 узлов. В тесной позиции двух змей на стандартной карте лимит растёт до 4 800, а бюджет времени остаётся `SEARCH_MS=75`. Явно заданный `SEARCH_NODES`, отличающийся от 1200, сохраняет свой лимит. В начале дуэли змейка проверяет ближайшую безопасную еду. В тесном проходе она учитывает освобождение своего хвоста и возможность соперника перекрыть выход. Верхний предел — 120 мс. Из `game.timeout` вычитаются ещё 150 мс запаса. При одновременных запросах на одном ядре только одна дуэль ведёт глубокий поиск, остальные получают быстрый рассчитанный ответ. Для локальных соперников доступны `STYLE=food`, `space`, `press` и базовая стратегия `baseline`.

## Проверки и воспроизводимые эксперименты

Нужны Go, Python 3.9+ и Make. Из корня чистого клона:

```sh
make test build cli
python3 tools/tournament.py --first-seed 1001 --seeds 12 --out .work/screen
python3 tools/tournament.py --first-seed 2201 --seeds 50 --out .work/control
```

Стенд сам поднимает локальных игроков. По умолчанию каждый старт используется дважды с обменом фактическими клетками игроков. В массовых режимах флаг `--rotations 4` ставит каждого участника на каждую из четырёх клеток. Стенд проверяет расстановку и стартовую еду каждой партии. На одном ходу движок передаёт одно и то же состояние участникам по очереди, затем одновременно применяет их решения. Заданный `--out` должен быть новым каталогом. В нём появятся параметры запуска и хеши бинарников, JSONL-повторы, результаты каждого матча и сводка. Серия с сетевой ошибкой завершается ошибкой. Параметр `--mode` принимает `duels`, `standard`, `royale` или `constrictor`. Для сравнения отдельных релизов передать `--binary`, `--reference-binary` и `--opponent search`. Для Constrictor CLI v1.2.3 использует карту standard, правила constrictor и нулевой спаун еды.

Чтобы проверить задержку, запустить контейнер на одном ядре командой из раздела запуска. Затем выполнить:

```sh
python3 tools/loadtest.py --url http://127.0.0.1:8080 --requests 1000
```

В комплекте 206 позиций, включая 138 ходов рейтинговых поражений и побед. Они доступны в [корпусе повторов](testdata/replays). Четыре стартовых запроса получены по HTTPS от арены во время рейтинговых партий и сохранены в [testdata/arena](testdata/arena). Ещё 64 позиции из локальных партий официального CLI охватывают дебюты, середины игр и последние ходы. Половина HTTP-запросов выполняется последовательно, половина с четырьмя одновременными играми. Скрипт проверяет статус и направление, измеряет полный обмен с клиентом и возвращает ошибку при p99 от 200 мс или любом результате от 500 мс.

## Проверка мест для сдачи

Команда читает открытые таблицы арены, сравнивает место Floodline с каждым из четырёх эталонов в Duels и проверяет место владельца в общем рейтинге. Снимок содержит время UTC и предварительный балл по правилам курса. До завершения калибровки арена указывает `placement`.

```sh
python3 tools/standings.py
```

## Публикация

Подключить этот репозиторий как сервис Railway. Конфигурация задаёт Dockerfile, одну реплику в Амстердаме, проверку `GET /` и постоянно работающий процесс. В настройках сети нажать **Generate Domain**. Зарегистрировать полученный HTTPS-адрес в Battlesnake, выбрать европейский регион и присоединить одну змейку к каждому из четырёх рейтингов. При `CAPTURE_SAMPLES=1` в лог попадает первый стартовый запрос каждого сочетания карты, правил и числа участников.

Спецификация доступна в [документации Battlesnake](https://docs.battlesnake.com/api/webhooks). Симулятор и стратегии Floodline написаны самостоятельно. Официальный [Battlesnake Rules v1.2.3](https://github.com/BattlesnakeOfficial/rules/tree/v1.2.3) используется для проверок и тренировочных партий.
